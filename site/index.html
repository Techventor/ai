老牌与新来的

两个轴都是对数刻度。横轴越靠右 star 总数越多，纵轴越靠上吸星速度越快。 成熟框架集中在右下角——体量大，相对自身规模增长慢。鼠标悬停看明细，点图例可以只看某一类。

标记含义，以及这份榜单看不到什么
suspect-stars
star 超过 5000，但每 100 个 star 还不到 1 个 fork。真实项目会被 fork： langchain 约 0.10，pytorch 约 0.27，而买来的 star 通常低于 0.01。 命中后分数打 55 折。
solo-project
几千 star 但贡献者不超过 2 人。不一定是坏事，但谈不上社区影响力。
no-license
没有许可证文件，别人法律上不能依赖它。
issue-backlog
未关闭 issue 超过 star 数的 8%。
too-new
建仓不足 21 天，还看不出来。
not-software
awesome-list、教程、路线图。已从榜单剔除——它们靠 star 赢，但不是软件。
缺失的信号
贡献者数和 90 天提交活跃度需要单仓库 API 调用。没取到时 community 会退化成用 fork 数代替，页面顶部会标注。
完全没测的
依赖数（dependents）是 GitHub 上最强的影响力信号，但 REST API 不提供， 只能爬 HTML 页面，太脆。更好的替代是各语言包管理器的下载量。
